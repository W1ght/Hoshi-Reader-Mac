## Current State

- Release: `v1.4.x` is the current Niratan macOS release line. Tag-triggered GitHub Actions is the release-validation source of truth: its validation gate runs native/full-build contracts plus the current high-risk Reader window/statistics regressions before packaging can start, and a release is complete only after the full-feature DMG, checksum and GitHub Release are published. The pipeline signs the App and nested code with `HOSHI_RELEASE_SIGNING_IDENTITY` when release-signing secrets are configured, otherwise falls back to valid ad-hoc signatures, and publishes an unnotarized DMG with checksum. Stable certificate signing is required for macOS TCC to preserve cross-app lookup Accessibility trust across app updates; ad-hoc packages can still require deleting and re-granting the Accessibility row after an update. The release asset is `Niratan-Mac-<version>.dmg`.
- Reader: the native content layer uses the complete GeometryReader viewport, extends into the top safe area to avoid wasting the titlebar band, stays out of the leading/trailing rounded-corner safe areas, applies only user-selected Reader padding, and consumes a final partial page before changing chapters, matching the `v0.5.0` Catalyst layout semantics without fixed side masks or chrome-derived text insets. Dedicated Reader windows explicitly restore and save the last valid windowed frame after both window close and App relaunch; they do not attach AppKit automatic frame autosave, because the closing SwiftUI root can temporarily collapse after coordinator reset, and full screen does not overwrite the windowed record. Teardown disables AppKit auto-release, uses weak window ownership and defers the presenter's sole release without capturing the window or forcibly detaching the live SwiftUI hosting tree; the window coordinator retains one model per open request, each model owns one statistics timer/open-sync, and statistics writes reject models that no longer own the persisted bookmark. Reader navigation structure remains a high-risk area.
- Lookup interaction: Reader and Popup restore the v0.5 Shift-hover scan path, while Video subtitles share the click/Shift-hover lookup path but retain native AppKit drag selection and copy. Lookup matches remain highlighted for the Popup lifetime. Reader, Video and nested definition Popup selections carry an ephemeral sentence context into the shared card-stacked context miner, with independent add/rollback controls on each side; actual EPUB/video pointer and context-mining behavior still needs an in-App manual pass.
- Validation tooling: the generated-fixture/Debug Lab/screenshot-baseline pipeline, Reader/Video/shortcut aggregate harnesses, and Reader-specific CI workflow have been removed. Narrow unit/static checks remain available by concern, while Reader completion claims require real EPUB validation in the exact `moe.shishamo.hoshi` build.
- Mac native migration: target, app identity, UIKit/Catalyst branches, ShareExtension coupling, legacy Reader wrappers, build scripts, and DMG workflow have moved to the single native `Niratan` App.
- Native open routing: Finder document opens and `hoshi://search` / `hoshi://open` requests now route through the native sidebar into the existing bookshelf import and dictionary search surfaces.
- Z-Library import: the native Bookshelf opens a Reader/Video-shared EAPI sheet backed by a user-configurable HTTPS origin. Login exchanges credentials for a host-bound `remix_userid` / `remix_userkey` session stored through an update-first Keychain write without retaining the password; non-default origins require explicit host confirmation. Search, recently added, and download history keep independent result/page/selection/scroll/detail caches and per-entry sort preferences. Search defaults to Japanese, remembers filters and up to eight individually removable queries, accepts numeric-only years, exposes active-filter reset, and requests EPUB only. A serial multi-book queue keeps the result surface open, supports per-item cancellation/progress and imported/duplicate/failure summaries, and refreshes quota after each received file.
